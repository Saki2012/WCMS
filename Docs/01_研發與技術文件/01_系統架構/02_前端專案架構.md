## 4. 前端啟動與 SSR 架構

### 4.1 SSR Server

`src/SSR/SSR-Server.ts` 是 Node／Express 對外入口，負責：

- 讀取環境設定。
- 建立 HTTPS／Proxy 執行環境。
- 開發時接 Vite Middleware。
- 正式環境提供 `dist/CSR` 靜態檔。
- 載入 `dist/SSR/entry-server.js`。
- Proxy `/Service` 至後端 API。
- 建立 CSP Nonce。
- 設定 HTML、靜態資源與 API Proxy 安全標頭。
- 移除 `Server` 與 `X-Powered-By`。
- 注入 SSR Initial State。
- 避免 HTML／API 被快取。

### 4.2 Server Entry

`Entry-Server.tsx` 負責：

```text
Request URL
→ 依前台／後台載入 Assets
→ AppRouteModule
→ createServerRouter
→ 執行 React Router Loaders
→ renderToString
→ Helmet Head Tags
→ Initial State
```

Provider 順序目前包含：

```tsx
<MessageProvider>
    <HelmetProvider>
        <HeaderMetaComp />
        <StaticRouterProvider />
    </HelmetProvider>
</MessageProvider>
```

### 4.3 Client Entry

`Entry-Client.tsx` 負責：

```text
初始化 Trusted Types／XSRF
→ 依 Route 載入 Assets
→ 讀取 SSR Initial State
→ 建立 Client Router
→ 判斷可否 Hydrate
→ hydrateRoot 或 createRoot
```

Hydration 判斷目前依賴：

- Root 是否存在實際 SSR DOM。
- Initial State 是否存在。
- `hydrationData` 是否為有效 Record。

> [!WARNING]
> 目前 Entry Client 仍有 `console.error` 用於 Initial State Parse、Hydration Recoverable Error 與 CSR Fallback。依新的 Release 規範，這些必須改由正式診斷／錯誤回饋機制處理，不能直接視為最終完成狀態。

## 5. Route 架構

### 5.1 AppRoute 聚合

`AppRouteModule` 將三種 Route 合併：

```text
前台 Feature Routes
+ 後台 Routes
+ Spec Custom Routes
```

入口：

```ts
const frontendRoutes = await loadClientChildren(ctx);
const backendRoutes = new BackendRouteModule().getRoutes();
const customRoutes = await getCustomRoutes();
```

### 5.2 全域語系 Route

`SysCore/Utils/Route/Routes.tsx` 將實際模組包在：

```text
/:lang
/
```

並負責：

- 語系正規化。
- LangGuard。
- 404 Redirect。
- SSR Static Router。
- CSR Browser Router。
- Hydration Data。
- Route Tree 正規化。

### 5.3 前台動態 Route

`ClientRouter.tsx` 使用 PGID Registry 將站台／選單資料轉成 Route：

```text
SiteMenu / Site Routing Data
→ Normalize Site / Node
→ PGID Module Registry
→ Loader + Component
→ React Router RouteObject
```

目前標準模組包含：

- PageManagement。
- Announcement。
- FileArchive。
- Gallery。
- WebResource。
- Timeline。
- Survey。
- Material。
- Sitemap。

前台 Route 不只是寫死頁面，而是由後端站台資料與 PGID 對應生成。

### 5.4 後台 Route

`ServerRouter.tsx` 目前具有：

- `/Server/Login`
- `/Server/Logout`
- `/Server/Register`
- `/Server`
- `RequireAuth`
- Dashboard Layout
- Metadata-driven Server Module Routes
- 後台 404

後台功能 Route 主要由 `ServerModuleRoutesData` 與 `ServerMenuIndex` 建立。

## 6. API 與資料存取架構

### 6.1 APIBase

`APIBase.ts` 建立 CSR／SSR 共用 Axios：

```text
CSR
├─ baseURL: VITE_API_BASE_URL 或 /Service
├─ withCredentials
├─ Accept-Language Interceptor
├─ XSRF Cookie / Header
└─ 403 後補票並重試一次

SSR
├─ baseURL: SSR_API_ORIGIN + /Service
├─ Forward Cookie
├─ Forward Accept-Language
└─ Request-scoped WeakMap Cache
```

### 6.2 APIClient

`APIClient.ts` 目前負責：

- `ApiBaseService`。
- HTTP Error 轉換。
- `ApiDataService<T>` CRUD。
- QueryData／QueryList／Count。
- ModelDisplay。
- System API。
- File Preview／Download URL。

目前標準呼叫概念：

```text
Axios
→ ApiBaseService.CallApi
→ ApiDataService
→ Feature Service
→ Adapter
```

### 6.3 Feature API Adapter

Feature 通常建立：

```ts
type AnnouncementFormModel = components["schemas"]["Announcement"];

class AnnouncementService extends ApiDataService<AnnouncementFormModel>
{
    constructor(apiInstance?: AxiosInstance)
    {
        super(PGID.Announcement, apiInstance);
    }
}

export class AnnouncementAdapterImpl extends ApiDataAdapter<AnnouncementFormModel, AnnouncementService>
{}

export const AnnouncementAdapter = (...) => ...
```

目的：

- Feature 不直接散落 URL。
- CSR／SSR 可注入不同 Axios Instance。
- Loader、Query Hook、Action Hook 共用同一服務。
- 未來 REST／GraphQL 轉換時降低 Component 變動。

### 6.4 APIAdapter

`APIAdapter.ts` 目前同時提供：

- `createApiLoader`。
- `useApiQuery`。
- `useApiAction`。
- `ApiDataAdapter`。
- QueryData／QueryList／Count。
- Paged Query。
- Grid Query。
- Form Query。
- CUD Actions。
- Toast／Error 組裝。
- SSR Initial Data 套用。

它是目前前端資料框架核心之一，也因此是高風險集中區。

> [!WARNING]
> 後續 Code Review 應先確認對外契約，再決定是否拆檔；不可只因檔案大就機械拆分。

## 7. ApiResponse 現況

目前前端定義：

```ts
export interface ApiResponse<T>
{
    IsSuccess: boolean;
    SysMessage: SysMessageModel[];
    Data: T | null;
}
```

目前部分 Service 使用：

```ts
ApiResponse<T[]>
ApiResponse<ModelDisplaySchema[]>
ApiResponse<EnumOption[]>
```

後端目前則是：

```text
ApiResponse<T>
→ Data: IList<T>
```

因此目前存在泛型語意落差：

```text
前端 T 可能代表單筆或陣列
後端 T 固定代表 Data 陣列元素
```

此問題會影響：

- Query Hook Data。
- Loader Initial Data。
- FormModel。
- Grid。
- ModelDisplay。
- Null／Undefined。
- OpenAPI 產生型別。

這是前端 Code Review 的第一批 P0／P1 項目。

### 8.3 Spec Timing

Spec 可：

支援三種情境：

```text

Feature 有、Spec 有
Feature 無、Spec 有
```

### 8.4 Form ViewModel

- Mode。

- Data Adapter。
- Binding。
- Refs。
- Raw Data。
- Form Props。
- Actions。
- Loading。
- Errors。
- Refetch。

這表示 Feature Form 不應自行重建完整 Query、Binding、Toast 與 Toolbar 生命週期。

## 17. 目前前端主要風險

### P0／契約

- `ApiResponse` 與後端 Data Array 契約不一致。
- Schema 型別與手寫 Type 混用。
- Null／Undefined 語意不清。
- 非 2xx 與 Biz Error 處理界線需統一。

### P1／Runtime

- SSR／CSR Hydration。
- Browser API 邊界。
- Loader 重複 Fetch。
- Request Race Condition。
- Promise 與 Cleanup。
- `console.*`。
- React Warning。

### P1／Form

- Template、Hook、Component 責任。
- Binding 與 Closure。
- FormModel。
- Reference Data。
- EditGrid／Repeater Identity。

### P1／AA

- 複合元件 Keyboard。
- Focus 管理。
- Toast／Dialog 報讀。
- CMS 動態內容。
- Spec 版型差異。

### P2／維護性

- Legacy Assets。
- `SpecFetures` 拼字。
- 大型 APIAdapter。
- Utility 重複。
- Feature／Spec 複製。
