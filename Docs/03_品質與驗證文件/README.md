# 品質與驗證文件

本目錄保存用來確認 WCMS 是否符合架構、規範、功能、無障礙與資安要求的資料。

本分類不專屬 QA，RD、QA、無障礙檢測、資安檢測與 Release 驗收都可共同使用。

## 目前目錄

- [`01_AI白箱檢測`](./01_AI白箱檢測/)：保存由 RD 發起與判定、AI 協助分析的白箱檢測流程與規範，包含需求與單元檢測、專項檢測及全專案白箱回歸檢測。
- [`02_QA測試`](./02_QA測試/)：目前保存 QA／RD／AI 協作、Issue 開單流程及測試方向的 v0.1 說明文件。

目前內容仍屬初期策略與共同語言整理；已建立 AI 白箱檢測第一版流程，但尚未代表 Markdown 自動開單、CI 自動檢測、測試狀態流轉或所有專項規則已全面落地。

## 分類原則

- [`01_研發與技術文件`](../01_研發與技術文件/) 定義系統應如何設計與開發。
- 本目錄保存檢查實際程式與功能是否符合技術規範及專案要求的策略、規則與結果。
- [`02_專案與交付文件`](../02_專案與交付文件/) 保存整理後提供 PM、客服、主管或客戶閱讀的正式版本。
- 同一主題可同時包含 Markdown、Word、PowerPoint、Excel 或 PDF；應依主題與用途分類，不依副檔名拆散。

## 後續自動化方向

未來可逐步將白箱檢測、測試案例、缺陷提報與複驗資料整理為具固定欄位的 Markdown，供 AI 或 GitHub 自動化流程解析與建立 Issue。

在格式與流程正式定案前，不先將討論中的欄位、狀態或開單規則視為既有規範。
