# 全專案白箱回歸檢測

## 1. 目的與適用範圍

本規範用於對指定 Branch／Commit 的整份 WCMS 專案進行白箱回歸檢查，確認架構、規範、共用底層、Feature／Spec 邊界與高風險技術主題是否仍維持一致。

本檢測屬靜態、架構與契約回歸，不等同 QA 功能 Regression Test，也不能取代 Build、實際操作、AA、Freego、弱點掃描、效能或部署驗證。

## 2. 觸發時機

建議於下列情況執行：

- 大型共用底層或架構重構後。
- 累積多個重要 PR 後。
- 前後端契約大改版後。
- AI 大量修改累積後。
- 重要里程碑完成後。
- 合併 `Feature/Release` 前。
- 正式 Release 前。
- RD 指定的固定週期。

一般 PR 應完成本檢測的觸發判定，但通常不需要完整執行。

## 3. 檢測基準

至少記錄：

```text
【Repository】
【Branch】
【Code Commit】
【Rules Commit】
【比較基準 Commit／Tag】
【檢測日期】
【納入範圍】
【排除範圍】
```

若使用新版規則檢查舊版程式，報告必須明確註明，避免把後來新增的規範誤認為原版本當時已違規。

## 4. 分區執行原則

不得要求 AI 在單一回覆中一次掃描整個專案並直接產出大量修正。

建議依序分區：

1. 共通架構與文件一致性。
2. 前端架構與開發規範。
3. 後端架構與開發規範。
4. Feature／Spec 邊界與 Fallback／Override。
5. API、Model、Schema 與資料契約。
6. AA、SSR／Hydration 與多語系。
7. Cache、Security、Auditing、Error Handling 與日誌。
8. 重複實作、Legacy 與未落地規劃風險。

每一區完成後先由 RD 判定，再進入下一區，避免錯誤前提污染後續結果。

## 5. 執行流程

```text
RD 鎖定 Branch、Code Commit 與 Rules Commit
    ↓
AI 建立專案區域與入口清單
    ↓
依分區讀取架構、規範與實際程式
    ↓
執行規則比對、引用追蹤與契約核對
    ↓
區分既有問題、本次新增問題與無法確認項目
    ↓
去重、分級並提交 RD 判定
    ↓
依風險分批修正
    ↓
單元複驗與必要專項複驗
    ↓
高風險區域重新回歸
    ↓
RD 決定是否進入 Release Gate
```

## 6. 檢測原則

- 以正式架構與開發規範為主要判定依據。
- 區分目前正式能力、設計方向、尚未落地能力與 Legacy 相容內容。
- 不因大量命中關鍵字就推定大量問題。
- 相同根因造成的多處問題應合併成一項系統性發現，列出代表證據與影響範圍。
- 既有問題與本次版本新增問題應分開標示。
- 無法確認 Runtime、資料、環境或外部工具結果時，不得標示通過或失敗。

## 7. 結果分級與摘要

個別發現依 [`README.md`](./README.md) 的結果格式與信心程度輸出。

全專案摘要至少包含：

```text
【檢測結論】
【已完成分區】
【未完成分區】
【Critical／High 風險】
【系統性重複問題】
【Legacy／規劃中能力】
【無法確認項目】
【建議修正批次】
【Release Gate 建議】
```

問題嚴重度可使用：

- **Critical**：可能造成重大資安、資料破壞、權限繞過或全面性不可用。
- **High**：可能造成主要流程失效、跨 Feature／Spec 影響或重大契約破壞。
- **Medium**：局部功能、維護性或一致性風險，需要排程修正。
- **Low**：低風險規範偏差或局部改善。
- **Observation**：架構觀察或證據不足的建議，不代表確定違規。

## 8. 修正批次

全專案回歸發現不得一次全部修改。

建議依下列順序分批：

1. Critical／High 且證據明確。
2. 共用底層根因。
3. 受共用底層影響的 Feature。
4. Spec 同步與客製差異。
5. Medium／Low 與文件一致性。

每一批都應重新走需求與單元白箱檢測；涉及特定技術邊界時，再追加專項檢測。

## 9. 回歸完成條件

白箱回歸完成不等同正式 Release 通過。至少要明確記錄：

- 所有預定分區是否完成。
- Critical／High 是否已修正、接受風險或另有處置。
- 修正後是否完成單元與必要專項複驗。
- 哪些 Build、QA、AA、Freego、弱掃、效能與部署驗證尚未執行。
- RD 是否同意進入下一個 Release 或實際測試階段。
